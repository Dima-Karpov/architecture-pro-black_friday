# ADR-005: Хэш user_id для orders

- Status: Accepted
- Date: 2026-10-25
- Deciders: команда «Мобильный мир»

## Context

Задание 7 проектирует заказы магазина в `shop.orders`. Стенд остаётся как в ADR-002: `somedb.helloDoc`, ключ `name`, два шарда, маршрутизирует `mongos`. Приложение шард не выбирает. Этот ADR задаёт ключ коллекции магазина.

Заказ хранит id, клиента, время оформления, позиции, статус, сумму и геозону. Позиция — товар, цена на момент покупки, категория и количество. Остаток хранится в `products` и списывается по ключу из ADR-006.

Операции: создать заказ и сразу списать остаток, показать историю заказов клиента, показать статус заказа.

## Decision

**Хэшированное шардирование по `user_id`.**

```javascript
sh.shardCollection("shop.orders", { user_id: "hashed" })
```

История одного клиента и создание его заказа попадают в один шард. Разные клиенты дают разный хэш, записи чёрной пятницы не садятся в один чанк «сейчас». Урок ставит хэш на равномерную раскладку.

Вторичный индекс `{ user_id: 1, created_at: -1 }` сортирует историю на том же шарде. Показ статуса идёт вместе с id клиента: фильтр `{ _id, user_id }` остаётся точечным.

Схема полей и пример документа — в [архитектурном документе](../07-10.md). Создание заказа и списание остатка — два ключа, документы могут лежать на разных шардах: [07-order-stock.puml](../c4/07-order-stock.puml).

## Alternatives considered

- Диапазон по `created_at`. Монотонный ключ, все новые заказы в последнем чанке.
- Геозона. Мало значений, Москва перевешивает. История читается по клиенту.
- Хэш `_id` заказа. Запись ровная, история клиента обходит все шарды. Эта операция в задании есть.
- Статус. Слишком мало значений.

## Consequences

- Positive: создание и история одного клиента идут в один шард. Клиенты раскладываются по хэшу.
- Negative: статус только по id заказа, без `user_id`, уходит на оба шарда. Поэтому показ статуса фиксируем вместе с id клиента. Списание остатка идёт по `_id` товара и может попасть на другой шард.
- Follow-up: метрики горячего шарда — задание 8. Чтение с primary или secondary — задание 9.
