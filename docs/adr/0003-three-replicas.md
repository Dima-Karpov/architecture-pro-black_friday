# ADR-003: В каждом шарде один primary и два secondary

- Status: Accepted
- Date: 2026-10-22
- Deciders: команда «Мобильный мир»

## Context

ADR-002 режет `somedb.helloDoc` на `shard1` и `shard2`, в каждом шарде один узел. Отказ этого узла забирает свою половину документов. Второй шаг задания 1 копирует схему шардов и добавляет отказоустойчивость: у каждого шарда три реплики. `configSrv` остаётся одним узлом. Куда читать, primary или secondary, это задание не решает.

## Decision

Master-slave в виде replica set MongoDB.

В `shard1`: `shard1-1` primary, `shard1-2` и `shard1-3` secondary. В `shard2`: `shard2-1` primary, `shard2-2` и `shard2-3` secondary. Подпись группы: 1 primary + 2 secondary.

Запись идёт на primary. На secondary копия уходит асинхронно. Упал primary — новый выбирают голосованием. Чтение с secondary в этот ADR не включаем: предпочтение чтения решает задание 9. Драйвер по-прежнему ходит только в `mongos_router`. Хэш и ключ `name` из ADR-002 не меняются.

## Alternatives considered

- Multi-master. Писать можно на любой мастер, конфликты одновременных записей разруливает СУБД. Cложнее в настройке и допускает задержку данных. Его схема — горячий резерв во втором ЦОДе, а внутри ЦОДа остаётся master-slave. Стенд — один compose, второго ЦОДа нет. Задание 9 различает primary и secondary; при нескольких мастерах этого деления нет. Первый абзац урока про replica set («похож на multi-master») расходится с практикой того же урока: пишет драйвер на primary. Берём практику.
- Старый протокол master-slave до MongoDB 3.6.

## Consequences

- Positive: у данных шарда есть копия. Отказ одного узла шарда не останавливает набор, простой короче. Позже чтение можно увести с primary.
- Negative: пока реплика догоняет, на secondary старые данные: заказ, прочитанный сразу после записи, можно увидеть прежним. Запись только через primary — потолок шарда. Три копии едят диск, CPU и сеть. Выборы primary на время останавливают запись. За каким узлом следить, без мониторинга не видно.
- Follow-up: откуда читать, primary или secondary, — задание 9. Кеш списка — ADR-004. `configSrv` в этой схеме по-прежнему один узел.
