# ADR-001: Один pymongo-api и один MongoDB (As-Is)

- Status: Accepted
- Date: 2026-10-22
- Deciders: команда «Мобильный мир»

## Context

Перед чёрной пятницей лёг микросервис API, который ходит в базу, и за ним сайт и очереди заказов. Проектная работа поднимает отказоустойчивость и пропускную способность этого контура. Задание 1 сначала фиксирует стенд как он есть, и только потом рисует шарды, реплики и Redis.

В репозитории сейчас `compose.yaml` и `api_app/app.py`. Сервис `pymongo_api` собирается из `api_app/Dockerfile`, слушает `:8080`, берёт `MONGODB_URL=mongodb://mongodb1` и базу `somedb`. Рядом один `mongodb1` на `:27017`. Переменной `REDIS_URL` нет. Сайта и брокера очередей в compose нет: в кейсе они пострадали от падения API, на схему стенда не входят.

`GET /{collection}/users` спит одну секунду. Декоратор `@cache(expire=60)` подменяется пустышкой, пока `REDIS_URL` не задан. Ключи коллекций `orders`, `products`, `carts` здесь не выбираем: стенд наполняет `somedb.helloDoc`.

## Decision

As-Is документируем как текущий стенд:

- один процесс `pymongo-api` (сервис compose `pymongo_api`), порт `:8080`;
- один узел MongoDB `mongodb1`, порт `:27017`, база `somedb`;
- драйвер ходит напрямую в этот узел, `mongodb://mongodb1`.

Образ приложения в этом шаге не меняем. Публичные маршруты:

| Маршрут | Метод | Что делает |
| --- | --- | --- |
| `/` | GET | Имена коллекций, счётчики, топология MongoDB, флаг кеша |
| `/{collection}/count` | GET | Число документов коллекции |
| `/{collection}/users` | GET | До 1000 документов, `sleep(1)`. Кеш на 60 с только при `REDIS_URL` |
| `/{collection}/users/{name}` | GET | Один документ по полю `name`, иначе 404 |
| `/{collection}/users` | POST | Вставка документа `{ age, name }` |

`GET /` при одиночном узле отдаёт `replica_status = "No Replicas"` и `shards = null`. `cache_enabled` остаётся `false`.

## Alternatives considered

- Рисовать на As-Is два шарда, replica set и Redis. Это уже целевые схемы задания 1, а не то, что поднимает текущий compose.
- Включать сайт и очереди заказов из кейса. Их нет в `compose.yaml` и `app.py`, стрелку к ним не к чему привязать.
- Считать кеш включённым из-за `@cache` в `app.py`. Без `REDIS_URL` декоратор ничего не кеширует, второго сервиса в compose нет.

## Consequences

- Positive: схема C4 и этот ADR совпадают с compose и кодом. Потолок и отказ одного узла видны до следующих решений.
- Negative: один `mongodb1` — потолок записи и чтения и единая точка отказа данных. Список users ждёт секунду на каждый запрос. Падение API по-прежнему останавливает тех, кто от него зависит. Код кеша в приложении есть, на стенде он не работает.
- Follow-up: схемы шардов, реплик и Redis и отдельные ADR на каждый выбор. Сброс ключа кеша и чтение с secondary в этот ADR не входят.
