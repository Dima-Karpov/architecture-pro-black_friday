# ADR-006: Хэш _id для products

- Status: Accepted
- Date: 2026-10-25
- Deciders: команда «Мобильный мир»

## Context

Задание 7 проектирует товары магазина в `shop.products`. Стенд остаётся как в ADR-002: два шарда, маршрутизирует `mongos`, приложение шард не выбирает.

Товар хранит id, наименование, категорию, текущую цену, остаток по геозонам и дополнительные атрибуты. Остаток — массив `{ zone, qty }` внутри товара. Пример из задания: «Смартфон X», 50 штук в Екатеринбурге и 30 в Калининграде. Списание — одно обновление этого документа.

Операции: часто списывать остаток при покупке, искать по категории и диапазону цены, открывать карточку товара. Заказ создаётся своим ключом, ADR-005: списание и вставка заказа могут попасть на разные шарды.

## Decision

**Хэшированное шардирование по `_id`.**

```javascript
sh.shardCollection("shop.products", { _id: "hashed" })
```

Списание остатка и карточка товара — точечные операции по id, один шард. Относим хэш к товарам, когда равномерность важнее поиска по диапазону. Смена цены и остатка оставляет документ на том же шарде: ключ при обновлении тот же.

Каталог обслуживает вторичный индекс `{ category: 1, price: 1 }`. Запрос без `_id` уходит на оба шарда.

Схема полей и пример списания — в [архитектурном документе](../07-10.md). Связка с заказом — [07-order-stock.puml](../c4/07-order-stock.puml).

## Alternatives considered

- Категория. Мало значений. «Электроника» собрала бы большую часть операций на одном шарде. Метрики такого перекоса остаются заданию 8.
- Диапазон по цене. Фильтр по цене стал бы легче. Смена цены при диапазоне перевозит документ между чанками. Списание остатка идёт по id.
- Геозона как ключ. Остаток — массив `stock` внутри товара.

## Consequences

- Positive: карточка и списание попадают в один шард. Товары раскладываются по хэшу id. Обновление остатка оставляет документ на том же шарде.
- Negative: поиск по категории и диапазону цены — scatter-gather по вторичному индексу. Популярный товар может греть свой шард. Это риск ключа `_id`. Категория как ключ собрала бы те же операции на одном шарде, поэтому она отклонена.
- Follow-up: горячий шард и популярные категории — задание 8. Откуда читать карточку, primary или secondary, — задание 9.
