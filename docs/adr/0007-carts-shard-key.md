# ADR-007: Хэш session_id для carts

- Status: Accepted
- Date: 2026-10-25
- Deciders: команда «Мобильный мир»

## Context

Задание 7 проектирует корзины магазина в `shop.carts`: гостевые и пользовательские. Стенд остаётся как в ADR-002: два шарда, маршрутизирует `mongos`. Приложение шард не выбирает.

В задании два фильтра текущей корзины: `{ session_id, status: "active" }` и `{ user_id, status: "active" }`. Один `sh.shardCollection` задаёт один ключ на коллекцию. Документ хранит `_id`, `user_id`, `session_id`, строки `items` (`product_id`, `quantity`), статус (`active`, `ordered`, `abandoned`), `created_at`, `updated_at` и `expires_at` для TTL. Поля `owner_id` в схеме нет.

Операции: создать корзину гостю или новому пользователю, прочитать текущую, добавить или заменить товар, удалить товар, при логине слить гостевую в пользовательскую, пометить корзину заказанной.

## Decision

**Хэшированное шардирование по `session_id`.**

Поле обязательное и у гостя, и у вошедшего: после логина сессию не стираем.

```javascript
sh.shardCollection("shop.carts", { session_id: "hashed" })
```

Гость, добавление, удаление и смена статуса в этой сессии идут по `{ session_id, status: "active" }` и попадают в один шард. Индекс `{ session_id: 1, status: 1 }` обслуживает этот фильтр на шарде. Вошедший в той же сессии оставляет в фильтре `user_id` рядом с `session_id`: ключ на месте, запрос на один шард. Сессии разные, создание корзин раскладывается ровно. Урок называет хэш подходящим для сессий.

Слияние при логине: чтение гостевой по `session_id` — один шард; дописывание в пользовательскую только по `user_id` — оба шарда; гостевую помечаем `abandoned` снова по `session_id`. Маршрут — [07-cart-merge.puml](../c4/07-cart-merge.puml).

`expires_at` — TTL-индекс `{ expires_at: 1 }` с `expireAfterSeconds: 0`. На шардированной коллекции просрочку снимает каждый шард у своих чанков.

Схема полей и пример слияния — в [архитектурном документе](../07-10.md).

## Alternatives considered

- Только `user_id`. У гостя поля нет, такие документы садятся в один чанк.
- Синтетический `owner_id`. Поля нет в атрибутах задания, фильтры его не содержат. Запрос по `session_id` или `user_id` без шард-ключа идёт на оба шарда.
- `status` или `created_at`. Мало значений или монотонный край. В двух фильтрах задания общее только `status`.
- Хэш `_id` корзины. Запись ровная, чтение текущей корзины обходит все шарды.

## Consequences

- Positive: текущая корзина сессии живёт на одном шарде. Создание корзин раскладывается по хэшу сессии. Вошедший в той же сессии читается точечно: в фильтре есть `session_id`. Просрочку снимает шард, на котором лежит чанк.
- Negative: корзина только по `{ user_id, status: "active" }`, когда сессия неизвестна, уходит на оба шарда. Это шаг слияния при логине, если у пользователя уже есть корзина с другой сессии.
- Follow-up: таблица primary / secondary по операциям корзины — задание 9.
