# ADR-002: Два шарда, хэш по полю name

- Status: Accepted
- Date: 2026-10-22
- Deciders: команда «Мобильный мир»

## Context

ADR-001 фиксирует один `mongodb1`: потолок записи и чтения и единая точка отказа данных. Первый шаг задания 1 поднимает пропускную способность и режет коллекцию на два шарда. На стенде это `somedb.helloDoc`, практика курса вставляет `{ age: i, name: "ly"+i }`. 

На схеме `pymongo-api` ходит только в `mongos_router`. Роутер читает карту чанков с `configSrv` и отправляет запрос на `shard1` или `shard2`. В каждом шарде пока один узел.

## Decision

Три выбора.

**Хэшированное шардирование.** MongoDB на стенде умеет его и диапазонное. Практика курса: `sh.shardCollection("somedb.helloDoc", { "name": "hashed" })`. Хэш значения `name` определяет шард, документ едет целиком. Хэш обратно не разворачивается, одно и то же значение всегда попадает в один шард. В уроке такая вставка раскладывается 492 и 508.

**Маршрутизирует mongos.** Приложение шард не выбирает. Драйвер ходит только в `mongos_router`. Роутер читает карту чанков с `configSrv` и отправляет запрос на шард. Запрос с ключом `name` попадает в один шард. Запрос без ключа, в том числе список `GET /{collection}/users`, уходит на оба (scatter-gather).

**Ключ — поле `name`.** Значений много и они разные (`ly0`…`ly999`), хэш раскладывает их ровно. `age` — последовательность 0…999: для диапазона это один растущий край.

## Alternatives considered

- Диапазонное шардирование проще для поиска по интервалу, но данные легко перекашиваются. Этот перекос в кейсе закрывают задания 8 и 10.
- Динамическое само балансирует, но поиск сегмента — отдельный сервис и единая точка отказа. Урок его не даёт собрать.
- Геошардинг кладёт данные по региону. На стенде региональных данных нет. CDN в задании 6 — статика, не нарезка MongoDB.

## Consequences

- Positive: потолок одной машины снят. Отказ одного шарда не забирает все документы. Простой запрос по `name` идёт в один шард.
- Negative: запрос без `name` медленнее, чем чтение одной базы. Поиск по хэшу труднее диапазона. Ошибка ключа портит раскладку. Два шарда — предел этого задания, не схема на рост. Равномерность хэша не отменяет горячий шард по другому полю: это задание 8.
- Follow-up: реплики внутри шарда — ADR-003. Чтение с secondary и ключи `orders`, `products`, `carts` в это решение не входят.
